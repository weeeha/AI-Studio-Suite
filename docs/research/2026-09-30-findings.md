Cross-cutting:
- Five of six are dark-only; Cork Board is light-only and its paper/cork look is the product identity.
- Colours are baked into outputs in several tools (Motion Previs pose videos, Storyboard contact sheets and PDFs, ScriptBreak print sheets, Cork Board textures and stored card colours). These stay literal on purpose; only chrome moves to tokens.
- Accessibility is thin across the board (clickable divs, little keyboard support).
- Interop between the six is mostly aspirational. The only real code hand-off is Motion Previs → Blockout.

## Design system

- **Canonical tokens:** Minimal Design System, `@weeeha/ui` (`src/styles/globals.css`). Three layers: primitives (`--base-*`, `--ink-*`), semantic (`--surface-*`, `--text-*`, `--border-*`, radius/spacing/motion), shadcn aliases. Light + dark via `.dark`.
- **Consumption limits:** private, not on npm, ships source `.tsx`, needs React 19 + Tailwind v4. The four React forks are on React 18, and Vercel cannot resolve a `file:` path to a local folder.
- **Gates to port:** `check:tokens` (no raw hex/palette classes/off-scale values, ratchet baseline for legacy) and `audit:contrast` (4.5:1 for every text token on every surface).
- **Conformance:** `ds-architecture` checks a target repo stage by stage (`node scripts/conformance.mjs <repo>`); stages 00, 01 and 09 are built.
- **ds-harness** is newer and adds theme and finish axes; reference only, Minimal DS stays the token source.
- **Super-AI-Components** (canonical: `VV-DSGN-INC/Super-AI-Components`, read from `origin/main`): shadcn registry, Base UI only, React 19. Strong fits: `studio-shell`, `timeline-shell` + timeline primitives, `media-prompt-bar`, `model-picker`, `preset-grid`, `generation-grid`, `compare-viewer`, `property-inspector`, `kanban-view`.

## The CozyClay recipe (precedent for restyling a fork)

1. Pixel-identical refactor: rewrite literals that already equal a `:root` token, role-aware (background vs border vs text).
2. Name the remaining chrome colours as new local tokens at their current values.
3. One commit that changes only `:root` values to Minimal DS values, each annotated with its DS token; anti-slop cleanup goes in the same commit.
4. Port `check:tokens` (strict + ratchet baseline) and `audit:contrast` into the app's test runner.

Token names stay the app's own, so upstream merges rarely conflict.
